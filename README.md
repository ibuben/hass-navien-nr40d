# Navien NR-40D для Home Assistant

Локальная интеграция комнатного пульта **Navien NR-40D** (котлы Deluxe ONE и совместимые). Home Assistant сам принимает подключение пульта и управляет котлом без облака Smart TOK / Sphere.

Это отдельная ветка проекта. Рабочий MQTT-мост `navien-emu` (`/opt/navien-emu`) **не заменяется и не останавливается**. Его можно оставить как запасной канал.

## Что появляется в Home Assistant

| Сущность | Назначение |
|---|---|
| `climate` | Вкл/выкл, комнатная температура и уставка, пресет «Вне дома» |
| `select` «Режим отопления» | По комнате / по теплоносителю |
| `number` «Температура теплоносителя» | 40–80 °C |
| `number` «Температура ГВС» | 30–60 °C |
| `switch` «Вне дома» | Тот же away-режим, удобно для автоматизаций |
| `sensor` температура в комнате | Для графиков |
| `sensor` режим и ошибка | Текущий режим и расшифровка кода из инструкции |
| `binary_sensor` связь с пультом | Пульт подключён к интеграции |

Уставки принимаются только целыми градусами — так устроен пульт.

## Требования

- Home Assistant 2024.2 или новее
- Пульт NR-40D в той же сети
- Перенаправление облачных адресов пульта на хост Home Assistant:
  - `rust2.naviensmartcontrol.com`
  - `rust.naviensmartcontrol.com`
  - TCP-порты `7000`, `21001`, `21003`

Пока MikroTik (или DNS) указывает на `10.18.10.27`, работает MQTT-мост. Интеграцию можно поставить заранее: она будет ждать пульт, пока вы не переключите перенаправление на `10.18.10.37`.

## Установка

### Вручную

1. Скопируйте каталог `custom_components/navien_nr40d` в `/config/custom_components/navien_nr40d` на хосте Home Assistant.
2. Перезапустите Home Assistant.
3. **Настройки → Устройства и службы → Добавить интеграцию → Navien NR-40D**.
4. Оставьте адрес `0.0.0.0` и порты `7000,21001,21003`, если не нужно иное.

### HACS

Когда репозиторий будет на GitHub: HACS → Интеграции → Добавить репозиторий → этот репозиторий → тип Integration.

### Docker / HAOS

Контейнер Home Assistant должен принимать эти TCP-порты с хоста (режим `host` или проброс `7000`, `21001`, `21003`). Иначе пульт до интеграции не достучится.

## Как переключиться с MQTT-моста

1. Поставьте и добавьте интеграцию на `10.18.10.37`. Датчик связи будет «выкл», это нормально.
2. На MikroTik смените `dst-nat` для пульта: вместо `10.18.10.27` укажите `10.18.10.37`.
3. Пульт переподключится сам (обычно меньше минуты). В интеграции загорится связь, подтянутся статус и устройство.
4. Сущности MQTT-моста уйдут в unavailable. Сам `navien-emu` можно не выключать: он просто останется без клиента.

Откат — вернуть `dst-nat` на `10.18.10.27`.

Не направляйте пульт сразу на оба хоста и не поднимайте интеграцию на той же машине, где уже слушает `navien-emu`: порты заняты.

## Ограничения этой связки котла и пульта

Пульт сам сообщает, что функции нет, и команды игнорируются:

- летний режим «только ГВС»
- быстрый нагрев ГВС
- уставки с половиной градуса (25,5 °C)

Сервисное меню котла (`S.THE`, DIP, датчик улицы `G.oN`) через пульт недоступно — только с панели котла.

Недельное расписание в этой версии не пишется. Его удобнее держать автоматизациями Home Assistant.

## Отладка

Логи: **Настройки → Система → Журналы**, фильтр `navien_nr40d`.  
Диагностика: страница устройства → «Скачать диагностику».

## Связь с MQTT-мостом

| | `navien-emu` | эта интеграция |
|---|---|---|
| Где живёт | `/opt/navien-emu` на `10.18.10.27` | `/opt/hass-navien-nr40d` |
| Как говорит с HA | MQTT discovery | нативные сущности |
| Сервис | `navien-emu.service` | процесс Home Assistant |
| Статус | работает, не трогаем | готова к установке |
