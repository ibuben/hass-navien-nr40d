# Navien NR-40D для Home Assistant

[![hacs](https://img.shields.io/badge/HACS-Custom-orange.svg)](https://github.com/hacs/integration)
[![release](https://img.shields.io/github/v/release/ibuben/hass-navien-nr40d?include_prereleases)](https://github.com/ibuben/hass-navien-nr40d/releases)

Локальная интеграция комнатного пульта **Navien NR-40D** (котлы Deluxe ONE и совместимые). Home Assistant сам принимает подключение пульта и управляет котлом без облака Smart TOK / Sphere.

После установки в Lovelace появляется карточка `custom:navien-nr40d-card`: температура, уставка, нагрев, «Вне дома», режим отопления, теплоноситель и ГВС на одном экране.

## Карточка

Карточка появляется в «Добавить карточку», если загружен её JS. После обновления интеграции перезапустите HA и обновите страницу с Ctrl+F5. Если в поиске пусто, добавьте вручную:

```yaml
type: custom:navien-nr40d-card
entity: climate.navien_nr40d
```

Или **Настройки → Панели → Ресурсы → Добавить**: `/navien_nr40d/navien-nr40d-card.js`, тип JavaScript-модуль. Термостат в списках называется **Котёл**, само устройство климатом не является.

```yaml
type: custom:navien-nr40d-card
device: <id устройства>
entity: climate.navien_nr40d
```

Интеграция сама регистрирует JS-модуль. Связанные сущности (теплоноситель, ГВС, режим, связь, ошибка) карточка находит по устройству. При желании их можно задать явно:

```yaml
type: custom:navien-nr40d-card
entity: climate.navien_nr40d
name: Котёл
water_entity: number.navien_nr40d_water_temp
dhw_entity: number.navien_nr40d_dhw_temp
mode_entity: select.navien_nr40d_heating_mode
away_entity: switch.navien_nr40d_away
```

## Что появляется в Home Assistant

| Сущность | Назначение |
|---|---|
| `climate` | Вкл/выкл, комнатная температура и уставка, пресет «Вне дома» |
| `select` «Режим отопления» | По комнате / по теплоносителю |
| `number` «Температура теплоносителя» | 40–80 °C |
| `number` «Температура ГВС» | 30–60 °C |
| `switch` «Вне дома» | Тот же away-режим, удобно для автоматизаций |
| `sensor` температура, режим, ошибка | Графики и расшифровка кода из инструкции |
| `binary_sensor` связь с пультом | Пульт подключён к интеграции |

Уставки принимаются только целыми градусами — так устроен пульт.

## Требования

- Home Assistant 2024.2 или новее
- Пульт NR-40D в той же локальной сети, что и Home Assistant
- На маршрутизаторе нужно направить облачный трафик пульта на хост Home Assistant (см. ниже)

## Настройка маршрутизатора

Пульт сам ходит в облако Navien. Локальное управление появится только после того, как этот трафик начнёт приходить на Home Assistant. На любом маршрутизаторе с NAT или своим DNS это одна и та же задача: **подменить назначение, а не протокол**.

**Куда стучится пульт**

- хосты: `rust2.naviensmartcontrol.com`, `rust.naviensmartcontrol.com`  
  в других регионах могут быть `krst2…`, `ukst…` и похожие имена той же зоны `naviensmartcontrol.com`
- TCP: `7000` и диапазон `21000–21010`  
  на практике чаще всего `7000`, `21001`, `21002`, `21003`. Это запасные входы одного и того же канала, не разные службы. Если перехватить только часть списка, пульт периодически уйдёт на пропущенный порт мимо интеграции.

**Что сделать на роутере** — любой один из способов:

1. **Перенаправление назначения (DNAT / port forwarding / «виртуальный сервер»)**  
   TCP с пульта на облачные адреса и порты выше → IP Home Assistant, те же порты. Так удобнее всего, если пульт резолвит DNS сам и ходит на внешний IP.
2. **Локальный DNS**  
   Те же имена отдать на IP Home Assistant (статическая запись, «hosts», AdGuard, Pi-hole). Сработает, если пульт берёт DNS у роутера или у этого резолвера.
3. **Оба сразу**  
   Надёжнее: DNS указывает на HA, а DNAT ловит тех, кто уже закешировал старый адрес.

Имя пункта в веб-интерфейсе зависит от прошивки: Destination NAT, Port Forward, Virtual Server, Address Mapping, «переадресация портов». Нужно именно **переписать получателя пакета**, а не открыть порты пульта наружу.

Пока трафик ещё идёт в облако или на другой хост, интеграция просто ждёт: датчик связи будет выключен. Это нормально.

## Установка

### HACS

1. HACS → Интеграции → Пользовательские репозитории
2. Добавьте `https://github.com/ibuben/hass-navien-nr40d`, тип **Integration**
3. Установите **Navien NR-40D** и перезапустите Home Assistant
4. **Настройки → Устройства и службы → Добавить интеграцию → Navien NR-40D**

### Вручную

1. Скопируйте `custom_components/navien_nr40d` в `/config/custom_components/navien_nr40d`
2. Перезапустите Home Assistant
3. Добавьте интеграцию через UI

Адрес прослушивания по умолчанию — `0.0.0.0`, порты `7000,21001,21002,21003`. При необходимости добавьте остальные из ряда `21000–21010`.

### Docker / HAOS

Контейнер Home Assistant должен принимать эти TCP-порты с хоста (режим `host` или проброс `7000` и `21000–21010`). Иначе пульт до интеграции не достучится, даже если маршрутизатор уже перенаправляет трафик.

## Ограничения этой связки котла и пульта

Пульт сам сообщает, что функции нет, и команды игнорируются:

- летний режим «только ГВС»
- быстрый нагрев ГВС
- уставки с половиной градуса (25,5 °C)

Сервисное меню котла (`S.THE`, DIP, датчик улицы `G.oN`) через пульт недоступно — только с панели котла. Недельное расписание в этой версии не пишется: его удобнее держать автоматизациями Home Assistant.

## Отладка

Логи: **Настройки → Система → Журналы**, фильтр `navien_nr40d`.
